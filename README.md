# Climate Intelligence for Heatwave Monitoring, Prediction, and Early Warning

A ready-to-run Python mini-project that combines historical temperature analysis, machine-learning forecasts, heat-risk scoring, and a Streamlit early-warning dashboard. The bundled dataset is clearly labelled **synthetic demo data** so the app can be explored without internet access. When internet is available, the pipeline can download historical and forecast weather data from Open-Meteo.

> **Responsible-use note:** This is an educational prototype, not an official warning service, a medical heat index, or a replacement for India Meteorological Department (IMD) bulletins. All risk levels generated by the app are described as *modelled/project heat-risk signals*. Use official IMD and local-authority guidance for real-world decisions.

## What the project does

1. **Monitor:** analyse daily maximum/minimum temperature, humidity, rainfall, seasonal patterns, and historical heat-risk days.
2. **Predict:** train separate Random Forest regression models for daily maximum and minimum temperature using prior-day lags, rolling averages, and calendar seasonality.
3. **Early warning:** compare forecast maximum temperature with a smoothed day-of-year normal and calculate a transparent risk level and a 0–100 project-specific risk score.
4. **Explain:** show the risk reason, temperature departure, alert level, data source, and model feature importance.
5. **Compare regions:** select Pune, Mumbai, Nagpur, Delhi, and Ahmedabad and compare forecast peaks.
6. **Stress test:** use the dashboard's *What-if Tmax uplift* slider to simulate warmer forecasts and check whether the alert rules respond. Any uplifted alerts are explicitly labelled as simulations.

## Run on Windows PowerShell

Open PowerShell in the extracted project folder.

### 1. Create and activate a virtual environment

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, run this for the current terminal session and retry:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

### 2. Run the local pipeline

The bundled synthetic dataset lets this work offline. It trains models, calculates holdout metrics, scores historical risk, and creates the 7-day dashboard forecast.

```powershell
python src/run_pipeline.py
```

### 3. Start the dashboard

```powershell
streamlit run dashboard/app.py
```

### 4. Fetch weather data from Open-Meteo

When connected to the internet, run:

```powershell
python src/run_pipeline.py --refresh
```

The pipeline attempts to fetch historical data and a forecast for every configured city. If the API is unavailable for a city, the pipeline keeps the existing local data for that city or falls back to the ML forecast rather than stopping the full demo. Check the `data_source` and `forecast_source` columns and the banner in the dashboard to see whether records are synthetic or externally sourced.

## Model design

The project trains one model for maximum temperature and one for minimum temperature per city. Input features use only temperatures from earlier days:

- Maximum temperature lags: 1, 2, 3, 7 and 14 days
- Minimum temperature lags: 1 and 7 days
- Rolling means over previous 3, 7 and 14 days
- Annual and monthly cyclical seasonality features

Model evaluation uses a chronological holdout: earlier records are used for fitting and later records for testing. Reported metrics include MAE, RMSE, and R². Metrics from `synthetic_demo` data are for workflow validation only and are not a claim of real forecasting accuracy.

When available, the Open-Meteo forecast is the reference temperature used for the alert assessment, while the Random Forest output is shown separately to make the two sources comparable. Without a live forecast, the app uses a recursive ML forecast labelled as a fallback.

## Heat-risk logic

For each date:

```text
Temperature anomaly = Forecast daily maximum − Smoothed day-of-year normal
```

The dashboard uses a transparent heuristic based on absolute maximum temperature, positive temperature departure from normal, and region type. It includes IMD-referenced temperature thresholds for educational comparison. The exact thresholds and regional handling are in `classify_risk()` inside `src/climate_pipeline.py`.

The 0–100 risk score combines temperature, positive anomaly, and relative humidity. It is a **project-specific prioritisation score**, not the official IMD severity index and not a clinical heat-stress index.

Official heatwave declarations involve more than a single modelled daily number, including station-specific observations, duration, regional coverage and operational assessment. This project must not describe its generated risk levels as official IMD alerts.

## Data sources

- Open-Meteo Historical Weather API: https://open-meteo.com/en/docs/historical-weather-api
- Open-Meteo Forecast API: https://open-meteo.com/en/docs
- India Meteorological Department heat-wave criteria and bulletins: https://mausam.imd.gov.in/pdfs/heatcolduser/morning_heat_bulletin.pdf

The configured locations and coordinates are in `src/config.py`. To add a location, add its latitude, longitude, state and `region_type` (`plains` or `coastal`) to `CITIES`.

## Output files

| File | Purpose |
|---|---|
| `data/historical_risk.csv` | Historical temperatures, normals, departures and risk levels |
| `data/forecast_results.csv` | Forecasts, Random Forest predictions, normal departures and risk scores |
| `data/alerts.csv` | Forecast days with a non-green modelled heat-risk level |
| `data/model_metrics.csv` | City-wise chronological holdout results for Tmax and Tmin models |
| `data/model_feature_importance.csv` | Random Forest feature importance for model inspection |

## Suggested demonstration flow

1. Open the Command Center and select a city.
2. Compare observed Tmax/Tmin with the seasonal normal.
3. Inspect the ML prediction and the forecast used for risk assessment.
4. Review the risk reason, departure from normal and forecast data source.
5. Increase **What-if Tmax uplift** to simulate a heatwave scenario and see warning levels respond.
6. Compare seasonal risk-day distributions and model metrics across cities.
7. Explain why synthetic demo results must not be treated as actual weather warnings.
